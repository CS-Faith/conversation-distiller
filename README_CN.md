## 这是什么？

每个 AI Agent 都会积累成百上千次对话。绝大多数知识在会话结束的那一刻就丢失了。**对话蒸馏器**会抓取对话中的决策、踩坑和洞察，蒸馏成永久的、互相关联的知识文章——让下一次对话无缝接续上一次。

## 为什么需要它？

| 没有蒸馏器 | 有蒸馏器 |
|-----------|---------|
| ❌ 上下文满了——从零开始 | ✅ 新会话读 wiki，什么都知道 |
| ❌ 同一个坑反复踩 | ✅ 每个坑都记录了：症状→根因→修复 |
| ❌ "上次我们怎么决定的？" | ✅ 每个决策都保留了因果推理 |
| ❌ 800+ 次对话知识散落各处 | ✅ 16 篇文章覆盖 11 个问题簇 |
| ❌ 新 Agent 开局一片空白 | ✅ 文章形成双向引用网络 |

## 工作原理

```
对话记录 → 适配器 → 蒸馏引擎 → 结构化知识文章
              ↑                      ↓
        Agent 自动发现         七段式模板
        （每个平台一次）        10项质量闸门
                              双向 wikilink 引用
```

### 1. 自适配输入
首次加载时，Agent **自动发现**当前平台的对话存储方式（JSONL / JSON / Markdown / 数据库…），自己写适配器。零手动配置。

### 2. 蒸馏引擎
- 新对话匹配已有问题簇
- 同簇更新 / 新簇新建
- 严格按**接力七段式**模板撰写（问题→状态→决策→踩坑→依赖→待办→完成定义）

### 3. 质量闸门
每篇文章入库前必须通过 **10 项必检**——包括踩坑三要素（症状→根因→修复）、可执行的动作、双向交叉引用。

## 快速开始

1. **安装** `SKILL.md` 到你的 AI Agent 的 skills 目录
2. **说**「对话入库」或「蒸馏」
3. Agent 自动发现你的对话格式 → 写适配器 → 开始蒸馏

## 支持的平台

蒸馏引擎**平台无关**。适配器示范代码包含：
- **Reasonix / PortaKit**（`.jsonl` + `.meta.json`）
- **ChatGPT**（`conversations.json` 导出）

其他平台：Agent 首次运行时自动编写适配器。

## 文章模板

每篇蒸馏文章结构：

```yaml
frontmatter:
  status, key_decisions, known_traps, related_articles, completion_criteria

正文:
  1. 这是什么问题？     （≤3句话，"如果你需要X…"）
  2. 当前状态            （里程碑+百分比）
  3. 关键决策与因果       （为什么，不只是做了什么）
  4. 踩过的坑            （症状→根因→修复）
  5. 接口与依赖
  6. 待办与下一步         （原子动作）
  7. 完成定义
```
